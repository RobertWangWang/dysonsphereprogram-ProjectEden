# 伊甸园计划 / Project Eden

把《戴森球计划》的后期产线整体拉满的 BepInEx mod。

十六座巨型建筑、满级采矿机与物流站、十二种新矿脉，一整条从煤和水通到有机化学的化工链
（C1 → 烯烃 → 芳烃 → 高分子，外加把一桶原油切成四个馏分的炼油线），
逐台建筑可调的合金配比、随货物流动的**物品品质**、5000 层传送带集装——**所有数值都写在 JSON 里，装完就能改。**

> 开发与测试基于游戏版本 **0.10.34.28529** ／ BepInEx **5.4.17**

## ⚠️ 先看这里：存档兼容性

### 1.12.1 起：行星放大默认开着，老存档会作废

半径从 200 变成 400，而**建筑坐标存的是行星局部坐标、模长约等于半径**——
所以在 **1.12.0 或更早版本下存的档，用这一版打开，每一座建筑都会在地下 200 格**。
没有回头路。

**要继续用老存档**：在 profile 里新建 `BepInEx\config\ProjectEden\planet.json`，写

```json
{ "enabled": false }
```

重开游戏即可，不用重新编译。开机日志会明确报出当前是开还是关。

**要用这个功能**：开一局新档，之后**不要再改那个倍率**——改倍率同样等于重开档。

### 下面这条对所有版本都成立

**装了这个 mod 之后存的档，卸载后就打不开了。** 不是「缺物品图标」那种降级，是真的读不出来。

本 mod 带一个 **preloader**（`BepInEx/patchers/` 里那个 DLL），它在游戏程序集装载前把传送带货物的
两个字段加宽了——这是「高层集装 + 满级增产剂同时成立」的前提——货物块的存档格式因此从版本 2 升到 3。

- 装 mod **之前**存的老档仍然能开（会自动按老格式读），**反过来不行**
- 除此之外还会往存档写新物品、新配方、新矿脉类型、**每格货物的品质点数**，以及一个独立的 `.moddsv` 伴生文件
- **没有干净的退回原版的路。要退就回备份。**

**强烈建议开新档**，或者动手前把 `%USERPROFILE%\Documents\Dyson Sphere Program\Save` 整个复制一份。

## 安装

**1. 先装八个前置**，都在 Thunderstore 上，装进同一个 profile：

| 前置 | 版本 | 作用 |
|---|---|---|
| BepInEx | 5.4.17 | mod 框架 |
| LDBTool | 3.0.3 | 注册新物品 / 配方 / 矿脉 |
| CommonAPI | 1.6.7 | 合成面板的自有分页 |
| DSPModSave | 1.2.2 | 本 mod 自己那块存档数据 |
| InstantDelivery | 1.2.0 | 物流即时送达 |
| ErrorAnalyzer | 1.3.3 | 报错时直接给出可读的堆栈 |
| UXAssist | 1.5.8 | 一批操作体验改进 |
| CloseError | 1.0.0 | 关掉挡住画面的报错弹窗 |

**前四个缺任意一个，游戏启动即报错**——它们是真正的代码依赖。
后四个不是本 mod 跑起来所必需的，列进依赖是为了**让所有人的环境和这边一致**：
这个 mod 的每一次验证都是在装齐这八个的 profile 里做的，
日志、行为、兼容性的结论全部来自那个组合。

**2. 导入本体**：r2modman 左侧 `Settings` → `Import local mod` → 选发布包的 zip，
然后从 r2modman 点 **`Start modded`** 启动（直接开 Steam 不会加载 mod）。

手动安装的话，包里的 `plugins/` 和 `patchers/` 要分别落到 profile 的两个目录下：

```
plugins/ProjectEden.dll          →  BepInEx/plugins/ProjectEden/ProjectEden.dll
plugins/Newtonsoft.Json.dll      →  BepInEx/plugins/ProjectEden/Newtonsoft.Json.dll
patchers/ProjectEden.Preloader.dll  →  BepInEx/patchers/ProjectEden/ProjectEden.Preloader.dll
```

> ⚠️ **`patchers/` 里那个不能漏，也不能放进 `plugins/`。** 放错位置**不会报错**：
> BepInEx 不去 `plugins/` 里找 patcher，插件启动后发现字段没被加宽，就按降级模式继续跑
> （集装退回 255、超过 63 层的增产剂被夹断），日志里写一行就过去了。

**3. 确认装对了**：`BepInEx/LogOutput.log` 里应该有这两行——

```
Project Eden v1.12.4 已加载
Cargo.inc / Cargo.stack 已加宽为 Int16（结构体 36 字节）：…
```

第二行是判断 preloader 有没有生效的唯一依据。完整说明见 **[部署.md](https://github.com/RobertWangWang/dysonsphereprogram-ProjectEden/blob/main/%E9%83%A8%E7%BD%B2.md)**。

## 改了什么

| | |
|---|---|
| **缺电会减速** | 巨型建筑的产能现在**随供电率线性下降**（50% 供电 = 一半产量），和原版 1 倍机器同一个口径。在这之前 10000 倍速对缺电几乎免疫——供电 11% 和 100% 产量完全一样，掉到 10% 以下才突然整台停摆 |
| **十六座巨型建筑** | 建造栏新增一页：天工装配厂、冶铸熔炉、燔石化工厂、锤锻精工厂、观微对撞机、生物温室、熔岩冷却厂、催化反应器、综合化学厂、氧化还原燃烧厂、同位提纯厂、奇点储能厂，外加反物质那四座（见下）。10000 倍速，12 个传送带口直连，自带行星内物流站；外形是**代码生成**的，十六座各不相同。实际产能原本被**原版自己的产出闸**按配方类型分三档封顶（冶炼 216,000 次合成/分钟、组装 36,000、其余 72,000），**1.12.8 起那道闸对巨型建筑抬到了统一的 216,000/分钟**——组装类 ×6、其余 ×3，普通装配机不受影响（分析面板的「参考速率」原本报的是一个引擎不允许的数，1.12.4 已夹回真实值）。其中几座各有一条额外规矩：**生物温室整座受日照约束**（满日照满产、背光面停工）；**催化反应器会记住床里那批催化剂还剩多少活性**——跑约十分钟就结焦失活，整床吹进待生仓，等再生炉烧完碳送回来；**氧化还原燃烧厂同时是一台发电机**，见下；**反物质那四座不是万倍速**，见下 |
| **大型采矿机 / 抽水站 / 原油萃取站** | 速度拉满、矿脉不消耗、机内缓存 1000 万；**产量上限已跟轨道采集器看齐（6 亿/秒）**——瓶颈原本不在开采速度而在「采矿周期」那个除数，现在按采集器的每 tick 上限倒推，两边共用同一个锚；**部分矿石直接产出冶炼后的成品**（铜→铜块、硅→高纯硅、钛→钛块、可燃冰→石墨烯、分形硅石→晶格硅、刺笋结晶→碳纳米管、**金伯利→金刚石**），铁/石/煤刻意保持原矿——它们的下游不止一条。只有大型采矿机换，普通采矿机和小型速采机照常出原矿。**小型采矿机**只放开机内缓存（50 → 10000，节流刻度同步放大），其余一律不动 |
| **小型速采机** | **开局那一台**：无前置、1 铁块 + 1 铜块手搓，恒定 **10000 矿/秒**、固定 1 MW，自带物流站槽位。它**不吃「矿物利用」科技加成、也不看脚下压着几条矿脉**——和大型采矿机不是大小之分而是两条曲线：早期够用、后期一点也不会更快 |
| **巨型建筑的两个面板** | 点开巨型建筑会**同时开出制造台和物流站两个面板**（左选配方、右管 30 个储物格），原版这两个面板本来会互相顶掉。储物格的**需求 / 仓储 / 供应现在可以自己改**：自动布局只决定哪一格放哪种货，方向只在指派时写一次、之后归你——想走传送带喂料就把原料格改成「仓储」，运输机和虚拟物流都会绕开它 |
| **换配方不丢东西也不变质** | 换配方时机器里的三处存货（储物格、已喂进去的原料、还没排出的产物）全部还给你；机甲装不下的掉在脚下，按堆叠分堆、不会过期。绝不会出现「100 个电路板换个配方就变成 100 个齿轮」 |
| **物流** | 物流站 30 格 × 1000 万，三种物流站统一 **5 GW 充能 / 150 GJ 储能**，运载与集装拉满：运输机 1 万 / 运输船 100 万 / **配送机 5000**（原版 5），运输机与配送机的**基础速度各 ×10**（乘的是基础值那一层，科技倍率照常叠加）。**单格容量是默认值不是锁死值**——面板上每格都能自己调，本 mod 只在新建时给默认、老存档抬一次。**30 格全都能用传送带喂料**（原版只有前 5 格能）；传送带白名单是原版的硬限制、只有 6 个位子，想要货的格子更多时按秒轮换，每格都轮得到 |
| **行星内运输机一帧多架** | 原版一个物流站**一帧最多派出一架**运输机——它的派机循环本来就会走遍整个供需配对环，只是一有收获就跳出去了。本 mod 把那三处「跳出」改成「还有额度就接着扫」，默认 **每站每帧最多 10 架**（`stations.json` 的 `localDispatchPerTick`，填 1 即回到原版）。**原版的派机判断一条都没有重写**，「电不够」的两处退出也原样保留；护栏（还有没有闲置运输机、电够不够）是逐字抄原版循环外那两道闸的 |
| **星际运输船一次多艘** | 原版一个星际物流站**一次派船评估最多放出一艘**船——和上面那条同一个形状：它的配对扫描本来就会走遍整段配对环，只是定下一对就跳出去了。本 mod 把那三处「跳出」改成「还有额度就接着扫」，默认 **一次评估最多 10 艘**（`stations.json` 的 `remoteShipsPerDispatch`，填 1 即回到原版，上限 64 = 一个站点至多只可能有 64 艘闲置船）。**同一条运输线也能连发**，默认最多 4 艘（`remoteSameRouteMax`）——只放开前者实测只有 2.28 倍、额度一次都没用满，因为放完一艘就往下一对走了。**原版的派船判断一条都没有重写**，「电力不足」那处退出也原样保留；同一条线能不能再来一艘由原版自己的记账收敛（每次派船当场扣两端，扣光了它自己换对）。<br>**另一半在评估频率上，而那一半不用改配置**：默认优先级的站点原版**一秒才被评估一次**，把取货那一端的站点设成「优先」直接 6 倍，两者相乘 |
| **背包每格 10000** | 所有物品的堆叠上限统一抬到 **每格 10000**（原版固体 100 / 流体 20），`stations.json` 的 `inventoryStackSize` 可调、填 0 回原版。源头只有 `ItemProto.StackSize` 一个，所以**背包、储物箱、物流背包、机甲的弹药与燃料格一起变**——做不到只改背包。老存档自动跟上：读档时游戏自己会按物品重写每一格的上限，所以调大调小都即时生效、不丢东西。这和传送带集装（5000 层）、物流站格容量（1000 万）是三套互不相干的东西 |
| **矩阵研究站** | 只改生产侧（造矩阵），科研速度没动；与物流站双向直通，不用铺传送带；七种矩阵配方统一 1 秒（这改的是**手搓**时间——研究站受每帧一周期的引擎上限约束，产能本来就已经顶到每秒 60 个） |
| **电力** | **卫星配电站全球覆盖**（26.5 → 2000 米，一座管一颗星）；**电力感应塔**覆盖 10.5 → 30 米、连接 22.5 → 60 米——这一项是为行星放大配的，4 倍表面积下原版那点覆盖要铺 4 倍数量。两者逐项可调（`power.json` 的 `nodes`），已建成的塔在读档时自动重建、用电建筑重新接入。新增 1000 倍风力发电机集群。它和可燃性液体发电厂**都能进制造台量产**，不再只能手搓（手搓仍然保留）——只有开局那台**小型速采机**是刻意保持手搓的 |
| **九种新矿脉** | 钴、铝、石膏、锂、锰、铬、钒、钨——素材全部复用铁矿脉运行时改色；另加一种**外星矿脉「莫桑石」**，只长在母星系之外，而且**挖它要消耗钻头** |
| **C1 化工链** | 煤 + 水 → 合成气 → 甲醇 → 甲醛 / 乙烯 / 丙烯，另有费托合成产精炼油 |
| **综合化学厂** | 第一台**能跑不止一种配方类型**的机器：化学、**精炼**、电化学、氧化还原四类全接，仍是 10000 倍速。原版「一台机器一种类型」是硬的，突破它改了八处闸门；而它**要吃 1000 台燔石化工厂**，所以那一座是它的前置，不是它的牺牲品。精炼是后补的：`石脑油 · 常减压蒸馏` 是石脑油和蜡油唯一的来源，却是精炼类，等于把整条有机化学链的入口钉在 1 倍速的原版精炼厂上 |
| **有机化学** | 三条主线都从 C1 链接出去：尿素与乌洛托品（给甲醛和二氧化碳找到去处，乌洛托品还是固体燃料）；丙烯腈 → 聚丙烯腈 → **碳纳米管**（氮在这条线上全额循环）；苯 → 异丙苯 → 苯酚 + 丙酮（异丙苯法，单进双出）。两条不同前置的树脂路线各自通向**原版塑料**：脲醛要氨（上游是气巨的氮气），酚醛要苯（煤和水就够） |
| **炼油：一桶原油切四段** | 常减压蒸馏把原油分成**石脑油 / 精炼油 / 蜡油 / 钒渣油**，四段各有各的下游：蒸汽裂解与催化重整吃石脑油、催化裂化吃蜡油、提钒与加氢脱硫吃渣油。加氢裂化把重的变成轻的，和催化重整构成氢的闭环 |
| **氮链 / 钨链** | 哈伯法制氨 → 奥斯特瓦尔德法制硝酸；白钨矿 → 三氧化钨 → 钨块 → 碳化钨 |
| **九种合金 + 四维属性** | 每种金属多四行属性（硬度／韧性／耐蚀／导电）；硬质合金的 WC:Co 配比**逐台建筑**用滑动条调，落到产量与制造时间上 |
| **五阶合金弹药** | 伤害与产量由**喂进去的那两种合金**决定，共用一条配方 |
| **岩浆与熔岩冷却厂** | 普通抽水站架到熔岩星上就能抽**岩浆**；熔岩冷却厂按三个真实的堆晶层位把它结晶回铬／钒／钴矿——同一套地质，正是当初把这三种矿放到熔岩与火山灰星球上的那一套 |
| **碳化硅电力电子** | 莫桑石的下游：籽晶升华长晶圆 → 氮化铝基板 → 功率模块 → **碳化硅能量枢纽**，服务同一批锂电池蓄电器，吞吐 5 倍 |
| **生物与活性材料** | 生物温室的三条链（零原料光合育林 → 藻菌共培养 → 提油）；菌丝基体把金属长成**活性复合材**（四档）；**第七种研究矩阵「生物矩阵」是养出来的不是合成的**，也是宇宙矩阵的第七味原料；原版之上再加两档增产剂，且分「浓缩」与「广延」两种性格 |
| **活性透镜** | 一枚**活的**引力透镜，进的还是原版射线接收站：**它在射线里愈合，在黑暗里老去**——满照下寿命是引力透镜的 2.5 倍，晒不到的地方照样十分钟烧完。发电 ×5、临界光子 ×3（两个倍率互相独立，都在 `lens.json` 里可调）。它在生物温室里**长**出来，要卡西米尔晶体、活性复合材、以及**碳化硅**——也就是说要先飞出母星系找到莫桑石。没找到也不要紧，原版那条引力透镜的路完好无损 |
| **氧化还原燃烧厂** | 唯一一台**既是组装机又是发电机**的建筑：把还原剂和氧化剂压成药柱，再把刚压出来的药柱当场烧掉发电，**药柱全程不上传送带**——所以它烧得掉金属粉和稠得挂壁的重馏分。面板上两行选料、一行**配氧比**滑条：氧化剂投少了烧不完、投多了是死重，而往上推能把药柱顶进更高一档。6 种还原剂 × 2 种氧化剂，输出 30 GW |

### 内容是按真实化学与物理推的

这不是风味文案，是每个数值的来源。新物品的属性全部**推导**而来，不是挑出来的：

- 配方配比来自**配平的化学方程式** —— `2 Al₂O₃ + 3 C → 4 Al + 3 CO₂` 就是矿 ×2 + 煤 ×3 → 铝块 ×4 + CO₂ ×3
- `isFluid` 看常温常压下的相态；`fuelType` 看它现实中到底烧不烧
- 热值按**燃烧焓**换算，全表锚在原版煤一个点上（2.7 MJ ↔ 393.5 kJ/mol）
- 用哪台机器看**反应类别**，不看方便：MTO 是脱水不是氧化还原，所以它留在原版化工厂

> 哪种还原剂能炼哪种矿，是按 Ellingham 图判的，不是按平衡感：
> 一氧化碳还原不了氧化铝，乙烯可以——判据是裂解后给不给得出**单质碳**。

每条配方的化学依据都逐条写在特性文档里（[中文](https://github.com/RobertWangWang/dysonsphereprogram-ProjectEden/blob/main/mod%E7%89%B9%E6%80%A7.md) ／ [English](https://github.com/RobertWangWang/dysonsphereprogram-ProjectEden/blob/main/mod_feature.md)）。

## 大工厂的逻辑帧

堆满巨型建筑的星球会卡逻辑帧，而这是 CPU 的事、和显卡无关。1.10.0 把一颗
**1078 台巨型建筑 + 894 台采矿机 + 1975 个物流站**的星球从 **25.2 ms 降到 6.7 ms**，
最高逻辑帧率 **40 → 142 ups**。三条优化，**没有一条改变产能**：巨型建筑不再空转结算、
没接输出带的物流站跳过出货扫描、巨型建筑批量结算（覆盖 98.9%，「生产设施」12.3 → 1.6 ms）。

批量结算带一个常设自检：定期把一台建筑的状态复制一份、在副本上跑真正的原版结算，
对不上就自动退回逐次并报错——**最坏情况是「没变快」，不是「数不对」**。
`megabuildings.json` 的 `batchSettle` 可以关掉它。

顺带一条实测出来的事实：**游戏的并行调度按星球分，一个工作项就是一整颗星球**，
所以单颗星球的逻辑帧加 CPU 核心不会变快——能动的只有「这颗星球上的东西更少」
和「把工厂摊到更多星球」。想自己看：统计面板 → 性能测试。

1.10.1 补上了**建造时**那一半。原版每放下一座建筑就把整颗星球的物流供需配对立刻重算一遍，
而那个算法是 **O(站点数²)**；本 mod 让每台巨型建筑同时是物流站，于是一颗成熟星球上
一次重算要 **81 毫秒**，建造时吃掉两成 CPU。改成最多每 2 秒合并算一次之后，
**每放一座建筑的开销从 102 毫秒降到 0.63 毫秒**。代价写在「已知取舍」里。

1.10.2 换掉了那个算法本身。配对的判据只有「物品相同 + 方向互补」，是一次**等值连接**，
所以可以按物品建索引——两千多个站点的星球上一次重建从 8900 万次比对降到约 64 万次，
**81 毫秒 → 6.7 毫秒**。它会定期跑一遍原版算法逐条比对，对不上就退回原版并报错：
**最坏情况是「没变快」，不是「配对错了」**。

## 已知取舍

不是 bug，是上面那些改动的必然副作用：

- 物流供需配对最多晚 2 秒重建：改完一格物品、新放一座站之后，无人机还会按旧配对飞两秒。**拆站不在此列**——拆除会立刻重建（1.10.6 起），延迟它会留下悬空引用而不是「晚两秒」，那正是 1.10.1~1.10.5 里那个会崩游戏的 bug
- 综合物流枢纽不会替你往伊卡洛斯的配送清单里加东西，清单空着配送运输机就不动（`autoDeliveryList` 可改回自动）
- 采矿机可以叠放，代价是它也能叠进别的建筑里，而且不能再原地重建/替换（叠放的建筑用蓝图复制后会照数粘出来——原版粘贴时只会建其中一座）
- 普通采矿机也能采原油（放行的两处代码指令特征完全相同，没法只放开一处）
- 原版化工厂也能做新增的「原油X射线裂解」（配方按类型生效，不按建筑）
- 巨型建筑的运输机数量、运送量、储能和格子容量仍由 mod 自动拉满，手动改了会被写回去（储物格的需求/仓储/供应不在此列，那个归你）
- 分拣器摆臂速度没有改，改的是集装层数和传送带速度
- 星际运输船一次多艘只管「一次评估放几艘」，**管不了「多久评估一次」**——默认优先级的站点原版一秒才评估一次，那一半要靠把站点设成「优先」，日志里每 60 秒会报一次全星系的优先级分布
- 行星内运输机一帧多架是拿 CPU 换吞吐：多派的每一架都多走一次配对扫描（最坏情况仍不超过原版——原版那个循环本来就以整个配对环为界）。逻辑帧变差就把 `localDispatchPerTick` 调小，日志里每 60 秒会报一次实际倍率
- 掉落过滤与信号选取窗口画不出第 14 列以后的物品（物品选取窗口有搜索框，不受影响）
- **叠在一处的同种建筑默认只画一台**（1.9.4 起）。几百台共位时，半透明层会逐层混合、加法层会逐份累加，画面会白得刺眼，而这不是把材质调暗能解决的——每一份压得再小，乘上台数都会累回来。逻辑一个字不动（采矿、耗电、点击、拆除、碰撞、小地图全照旧），只是显卡少画几份；拆掉看得见的那台会自动顶一台上来。想看见整摞就把 `advancedminer.json` 的 `stackedRenderLimit` 调大或留空

- 其余 mod 未系统测试

### UXAssist 的两个功能

本 mod 的 preloader 把传送带 API 的 `byte` 参数加宽成了 `Int16`（那是 5000 层集装的前提），
而 UXAssist 是按原版签名编译的。实测受影响的只有这两处，**其余功能一概正常**：

| 功能 | 状态 | 说明 |
|---|---|---|
| **传送带信号购买** | **用不了** | 从外部修不了也关不掉 |
| **矿脉保护** | **请关掉** | 和本 mod 的采矿机改造互斥，而本 mod 已提供同样效果 |

**传送带信号购买**：它调的那个签名已经不存在了。而且这个**没法从外部绕过** ——
Harmony 打任何补丁（哪怕只是加一个前置把它整个停掉）都必须把原方法体重新发射一遍，
而方法体里那条引用解析不出来，写回必然失败。要用它就只能卸掉本 mod 的 preloader，
代价是集装层数从 5000 退回 63。

**矿脉保护**：它的实现是一个**返回 `false` 的前置，整个跳过原版的采矿逻辑**。
而本 mod 的矿石→锭替换、机内缓存上限、钻头消耗、小型采矿机节流全都写在那段被跳过的代码里 ——
一开它，这些会**静默失效**（不报错，只是不再生效）。

**关掉它不损失任何东西**：本 mod 自己就让矿脉完全不消耗 ——
大型采矿机 / 抽水站 / 采油站由 `forceMiningCostRate` 覆盖，小型采矿机由 `protectSmallMinerVeins` 覆盖。
如果你忘了关，本 mod 会在采矿时检测到并在日志里提醒。

## 配置

配置是 **JSON 嵌入在 DLL 里**的，装完的包里看不到单独的文件。两种改法：

- **不用编译**：在 profile 里新建 `BepInEx\config\ProjectEden\<同名>.json`，它会盖掉内嵌的那份，重开游戏生效
- **改源码重新编译**：内容类配置（矿种、配方、数值）本来就跟着版本走，一般走这条

> 用了覆盖文件的话，日志里每次都会打一条 WARNING 把路径写出来——
> 一份忘了删的覆盖文件会让之后所有对内嵌 JSON 的修改看起来「没生效」。

## 出问题了

`BepInEx/LogOutput.log` 里搜 `ProjectEden`。

本 mod 的每一处改动都会打一行确认；**匹配失败会打 ERROR 而不是静默失效**，

## 参与开发

- **[部署.md](https://github.com/RobertWangWang/dysonsphereprogram-ProjectEden/blob/main/%E9%83%A8%E7%BD%B2.md)** —— 装给别人用怎么装、发新版怎么打包（含 preloader 的离线校验流程）
- **[CLAUDE.md](https://github.com/RobertWangWang/dysonsphereprogram-ProjectEden/blob/main/CLAUDE.md)** —— 架构说明与踩过的坑。读 IL 胜过猜，这份文档里的每一条机制都是这么来的

```bash
dotnet build                                   # 编译并部署插件到 profile
dotnet build ProjectEden.Preloader/ProjectEden.Preloader.csproj -c Release
powershell -ExecutionPolicy Bypass -File tools\verify_preloader.ps1 -Config Release
python tools\pack_release.py                   # 打发布包
```

> **preloader 改动后必须跑 `verify_preloader.ps1`。** 它在游戏程序集交给 CLR 之前重写它，
> 写错的表现是游戏启动失败、报一个不指向本仓库任何代码的 CLR 类型加载错误——
> 到那一步，平时那套「读 IL、报匹配数、匹配为 0 就大声失败」的办法一个都用不上。
