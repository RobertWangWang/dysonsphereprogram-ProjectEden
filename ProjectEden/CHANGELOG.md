### 修复：放大的星球上，掉在地上的东西到处漂流

根因有两处，**第一处是本 mod 自己的 bug**。

**（1）`AstroData.uRadius` 停在 200。**
`PlanetGen.CreatePlanet` @0AA9 有一句 `astrosData[planet.id].uRadius = planet.realRadius`，
而它在**方法体内**——我们改半径的后置是在它返回之后才跑的，所以那个字段拿到的是原版的 200。

掉落物物理因此判成：地面 = `uRadius + 0.35` = **200.35**，而掉落物在 400.x，
`距离 < 地面` 永远不成立，**它永远落不了地**。

**这个字段有 45 个读取方法**（枚举所得），所以受影响的远不止掉落物：星际船的到达时间与
派船判断、玩家导航、戴森球火箭、弹射器、战斗与敌人寻路——**全都以为放大过的星球只有 200 大**。
这一条修掉是连带受益的。

> 之所以漏掉，是因为早先那次「谁读 radius」的普查**只扫了 `ldfld`，没扫属性调用
> `get_realRadius()`**。枚举要连属性一起枚举。

**（2）`TrashSystem.Gravity` 里三个按半径 200 写死的常量。**

| 常量 | 是什么 | 在半径 400 上坏在哪 |
|---|---|---|
| **210** | 查不查真实地形的距离闸 | 永远不成立 → 地形根本不查，「地面」退化成光滑球，山上的埋进去、谷里的浮空中 |
| **800 / 150** | 重力强度斜坡 | 地表处 `10^(400/150)≈464` vs 原版 `10^4`——**重力弱 21 倍**，压不住切向速度，贴地滑走 |
| **600** | 岩质行星 / 气态巨星的判据 | 400 时还没坏，但半径一到 600 我们自己会被当成气态巨星、掉落物直接消失 |

修法是各加上「这颗天体比原版大出来的那一截」，于是变成 **410 / 1000 / 800**——
**半径 200 时增量为 0，和原版逐位相同**。`150`（斜坡陡度）不动，它和半径无关。

判据用的是**按天体 id 的标记表**而不是半径值：`astrosData` 里恒星和行星混在一起，
而恒星的 `uRadius` 是 `radius × 1200`、取值几百到上千，**有可能正好等于我们的半径**。

**这条修复对现有存档立即生效，不用新开档**——`uRadius` 每次读档都重算。

### 新增：大型采矿机挖金伯利矿，直接产出金刚石

不用再进熔炉。配置在 `advancedminer.json` 的 `productMap`，**一条数据，没写一行代码**——
这套「矿石在源头就冶炼」的机制本来就在（铜矿→铜块、可燃冰→石墨烯等六条），
金伯利正好是它设计时的形状。

- 矿石 ID 从 `VeinProto.MiningItem` 现查，产物从「**只吃这一种矿**的那条原版配方」推出来，
  原版只有「金刚石（高效）」符合。推不出来会打 WARNING 说清是「找不到」还是「找到多条」，
  **不会静默失效**。
- **它是这张表里最干净的一条**：金伯利矿石在原版只有金刚石这一个去处，
  没有第二个下游要吃矿石形态——对照那三种故意不换的（铁矿下游一大堆、石矿分石材和玻璃两路、
  煤矿既是燃料又是化工链原料），在源头冶炼掉不会掐断任何东西。
- **金刚石从石墨造的那条路完全不受影响**：这里只改采矿机挖出来的是什么，一条配方都没动。
- **只有大型采矿机换**：普通采矿机和小型速采机照常出原矿石，想要金伯利矿石本身仍然拿得到。

### 已知缺口：按半径 200 写死的常量很可能还有

这一版修的两处（网格数组的 `kMaxMeshCnt`、地基基准面的 `20020`）和上一版那两处，
都是**被具体症状逼出来的**，而不是系统性排查出来的。
一次启发式扫描（「方法里既读行星/天体半径、又含 150–900 之间的字面量」）标出 143 个方法——
其中绝大多数是 360/180 这类角度常量，属误报，**但它说明这一类还没有被穷尽**。
最可疑的是 `GameCamera.Logic`（155 / 192.8 / 220.95 / 255 / 200）。

**碰到「放大之后某个东西行为怪异」，请直接报**——这一类的定位路径已经很熟了。
