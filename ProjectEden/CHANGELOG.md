# 更新日志

## 1.11.0

**反物质产线**：四座新的巨型建筑，把只长在黑洞旁边的两种矿变成原版反物质。
外加三条实测出来的性能优化——这颗测试星球上「物流运输」那一栏每帧从 **7.6 ms 降到 5.0 ms**。

### 反物质：四步，四类不同的物理

| 建筑 | 配方 | 耗电 | 折算倍速 |
|---|---|---:|---:|
| **视界蒸发炉** | 吸积熔晶×6 + 视界凝核×1 + 单极磁石×2 + 铁块×1 → 霍金辐射×8 + 高能γ光子×4（35 秒） | 3000 MW | 30× |
| **磁分离塔** | 霍金辐射×8 + 单极磁石×1 → 反质子×2 + 氢×6（10 秒） | 480 MW | 8.6× |
| **对产生室** | 高能γ光子×4 + 碳化钨×1 → 正电子×2（8 秒） | 360 MW | 6.9× |
| **彭宁阱复合室** | 反质子×2 + 正电子×2 + 多孔吸气剂×1 → **反物质**×2 + 饱和吸气剂×1（8 秒） | 300 MW | 6.9× |

把一整柜的电压进针尖大的地方，让时空自己合拢，接住它蒸发出来的东西——那不是光，是一整个
温度谱上的全部粒子，**正反成对**。后面三座就是把那一包拆开：磁场把正反掰成两股、硬 γ 打钨靶
凭空造出正负电子对、最后在彭宁阱里复合。

**这四座不是万倍速。** 其余十二座巨型建筑都是 10000×，这四座每 70 tick 才结算一次。
动的是周期数不是 `speed`（巨型建筑靠 `speed >= 阈值` 识别，调低就再也不被接管了）——
代价是**制造台面板那一行「制造速度」仍然显示 10000×**，面板和实际产能在这四座上对不上，
这是已知的、没有办法的。

**能量账刚好打平，而且只在黑洞星系打平。** 一趟链产反物质×2、耗电 4.83 GJ，即每颗 **2.42 GJ**；
而一颗反物质烧成燃料棒只还回 **1.20 GJ**——净亏一半。**建在黑洞星系的这四座结算周期减半**，
耗电按 tick 算、和周期无关，所以电费也减半到 1.21 GJ，**恰好和烧回来的持平**。
在别处建它永远亏电，只有建在原料产地才划得来；而黑洞星系只有一颗行星（写死的，不是随机），
配套还全得反向运进去。

加成刻意**不挂恒星质量**：默认 64 星的一局只有 1 个黑洞，所以质量对一个存档而言是个常数，
挂上去玩家不是在做决策，是在抽种子（中位只有 1.19×）。

**吸气剂是闭环**：`活性复合材 I×3 → 多孔吸气剂×2`，吸满了 `饱和吸气剂×3 → 多孔吸气剂×2 + 氢×1`
加热再生。3 换 2，所以是条有损耗的闭环，不是永动的。

新增 6 个物品、6 条配方、4 种配方类型。

### 性能：三刀，全部先量后改

这颗测试星球：29251 个实体、4632 台巨型建筑、6397 个物流站、1764 台采矿机。

- **巨型建筑的物流站可以跳过派机空扫**（`stations.json` 的 `skipIdleMegaStationTick`，**默认关**）。
  原版的派机扫描「找到活就早退，找不到活就走完整圈」，而巨型建筑的货早被虚拟物流搬完了，
  永远找不到活——4632 台每 12.8 帧走一次整圈，约**每秒两万一千次空扫**。
  打开之后实测原版那一半 **−35%**。
  代价说清楚：它们**彻底不再派出行星内运输机**（那本来就是虚拟物流想达成的效果），
  所以默认关着，由你决定。
- **物流站容量引导不再每 tick 全量扫描**。引导本身一直是「每站一次」，可外面那圈遍历是永远跑的——
  实测**每帧 0.5 ms，是本 mod 挂在物流上最贵的一个**。改成「一趟什么都没改就停扫」，
  站点数变了或每 10 秒兜底重扫。实测 **604 ms → 23 ms**。
- 合计：「物流运输」那一栏每帧 **7.6 → 5.0 ms**。

### 诊断

- 新增 `perfprobe.json`（**默认关**）：把逐任务的 CPU 耗时打进日志，省掉人肉抄
  「统计面板 → 性能测试」那十行，并且能把**本 mod 自己的开销和原版的分开计时**——
  原版的分析器按任务计时，而我们的代码就在那个任务里面，它结构上分不出来。
- 新增 `tools/check_guides.py`：中英两份特性指南的 `##`/`###` 计数平行、TOC 锚点可解析，
  打包时一并检查。

### 修复

- 合成面板格位和建造栏槽位的几处冲突。同一个号在不同配置文件里用**不同的键名**存
  （`modelId` / `veinModelId`、`gridIndex` / `gridRow`+`gridCol`），只查一种拼法就会漏。
- `machines.json` 手工钉死的格位会被 `ores.json` 的自动分配抢走——注册顺序里它排在后面，
  登记得太晚。现在多一趟只登记不注册的预占。
