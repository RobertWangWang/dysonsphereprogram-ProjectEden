## 1.12.16

### 黑洞矿的第三个去处：超级磁场环 · 磁单极封装

两种黑洞矿原先各自只有一个下游（吸积熔晶 → 电离玻璃，视界凝核 → 凝核稳定剂），
两条都只通向蓄能柜那一条线。这一版给它们一个共同的、面宽得多的出口：**原版的超级磁场环**。

在**粒子对撞机**（类型 5，巨型建筑对应观微对撞机）里：

```
单极磁石 ×4 + 吸积熔晶 ×2 + 视界凝核 ×1  →  超级磁场环 ×10      10 秒
```

#### 三样原料各自对应磁体的一个硬约束

按本仓库的内容规矩，配比是**推出来的**，不是挑出来的——器件装配不是化学反应，
所以配比写的是功能对应关系，和合金那几条同一个处理方式：

- **磁单极是场源。** 常规磁环的场来自环流电流，受欧姆损耗和导体截面限制；
  磁单极是 `∇·B ≠ 0` 的真源，排成环就得到静态场，**一点电流都不需要**。
- **视界凝核是受力件。** 磁场强度的真实天花板是磁压 `P = B²/2μ₀`——100 T 就是 4 GPa
  （超过任何钢），1000 T 是 400 GPa（超过任何已知材料）。所以「能做到多强」
  等价于「什么能兜住这股环向应力」，简并态致密物质是唯一选项。
- **吸积熔晶是基体。** 它自己不导电却能兜住电浆（这正是「电离玻璃 · 熔融重整」那条的设定），
  而磁单极必须封在不导电的基体里，否则壳体里的涡流会把场慢慢耗掉。

#### 它和反物质线抢矿，这是有意的

视界蒸发炉吃的是 `吸积熔晶 ×6 + 视界凝核 ×1 + 单极磁石 ×2`——**同样三样东西**，
而视界凝核是全局最稀的一种（仅黑洞、每个黑洞 1 处、chance 0.35）。
所以这不是白送的捷径，是一次真实的取舍：**反物质还是磁场环**。
它卖的是「不必再建磁铁／磁线圈那条链」，代价是把最稀的矿分出去。

**原版那条超级磁场环配方不受影响，两条并存**，形状和原版自己的
「石墨烯／石墨烯（高效）」一样。和其余 `ores.json` 配方一样**开局即解锁**。

> **产量 ×10 和 10 秒是平衡旋钮，配比不是。** 要调就调前两个数（`ores.json`），
> 别动配比——那三条是从上面的物理推出来的。

**故意不画图标**：`SyncStandaloneRecipeIcons` 会让它跟随第一个产物，
也就是原版超级磁场环自己那张图。和「钛合金 · 真空重熔」同一个路子——
产物是原版物品，本来就有图，不必再画一张。三个 `vanilla:` 引用一律**按名字解析**、
不写死 ID；解析不到会 ERROR 并跳过整条配方，不会静默产出别的东西。

### 科技级联买断：用元数据买断深处的科技时，一并把前置买了

原版的规则是「前置没解锁就不能买断」，两道闸：`GameHistoryData.BuyoutTech` @0056，
以及 `UITechNode.OnBuyoutButtonClick` @001D（弹「存在未解锁的前置科技」然后直接 return）。
开着 `tech.json` 的 `buyoutCascade`（**默认开**），点深处科技的买断按钮会
**按拓扑序先把没解锁的前置逐级买断**，再买目标。

> **省的是点击次数，不是代价。** 闭包里每一级都走原版的 `BuyoutTech`，各付各的元数据。
> 原版另有 `UnlockTechUnlimitedWithAllPre` 能白送整条链，**这里刻意不用它**。

#### 前置判据是照抄的，不是按名字猜的

`HasPreTechUnlocked` 的循环是 `for (j = 0; j < 2; j++)`——`j == 0` 取 `TechProto.PreTechs`、
**`j == 1` 取 `PreTechsImplicit`**，两张表里每一条都要 `techStates[x].unlocked`。
只走 `PreTechs` 会漏掉隐式前置，而后果**不是报错**——是原版那道闸照样拦着，
表现为「点了没反应」。闭包遍历逐字照抄了这一条。

#### 付不起会怎样：停在那一级，已买到的保留，不回滚

这一点和「配方做到一半」不同：**中途停下不会浪费任何元数据**，玩家实实在在拿到了那几级科技，
只是没够到目标。所以代码里**刻意不做「全有或全无」的预检**——那反而会在余额刚好够前几级时
什么都不给。日志会打出停在哪一级。

#### 实现

引擎侧是 `BuyoutTech` 的一个前置（把缺的前置先买掉，**满足**原版那道闸而不是绕过它）；
UI 侧是 `OnBuyoutButtonClick` 里**两处 operand 各换一次**——两个替身的签名和被替换者
逐位一致（都是 `(GameHistoryData, int) -> bool`），所以栈形状不变、分支标签不动。

**两处必须一起换**：只换前置那处会被「元数据不足」拦住（原版那个判据只算目标科技自己的花费），
只换花费那处会被「存在未解锁的前置科技」拦住。数目对不上就**整体不改写**——
半个改写比不改写更难查。递归带 64 层深度上限，那不是性能考虑，是**防挂**：
科技表里一旦有环，闭包遍历会无限下去而游戏只会卡死、不报错。

### 卫星配电站的连接距离也放到 2000 米——覆盖不等于连通

覆盖早就是 2000（一座罩住整颗星），但**连接距离一直留在原版的 53.5**，
当时的理由写的是「一座就够，不需要连成网」。**那句话漏了一件事：**

> **DSP 里两个节点同属一张电网，靠的是 `conns`（连线），不是覆盖圈重叠。**

所以一颗星上放两座卫星配电站，会得到**两张互不相通的电网**——发电和用电不共享，
而两张网在画面上都罩着整颗星。玩家看到的是「明明都覆盖了，电却不通」。
两个范围都给到 2000 之后，全星球的配电站才真的连成一张网。

改动是 `power.json` 里的一行（这套设置本来就是逐项可配的），
存量修复也早就覆盖了它——`PowerCoveragePatches` 走的是原版的
`OnNodeRemoving → 改 → OnNodeAdded` 拆建流程，而那正是刷新 `connDistance2` 缓存的办法。

#### 顺带重新量了那条「不要动连接距离」的警告，它只对了一半

`PowerSystem.line_arragement_for_add_node` 确实是 **O(n²)**——三层嵌套循环
（后向分支跨度 349 / 303 / 17 条指令），遍历 `List<PowerNetworkStructures.Node>.Count`，
**每放一个节点跑一次**。但**那两层循环是照节点表跑的，和 `connectDistance` 无关**；
连接距离只决定有多少对真的连上。所以直接开销不变，真正变贵的是**电网会合并**，
合并后同一张网里的 n 变大，而 n² 正是那个循环的代价。

两件事让这笔账对卫星配电站划算：`Node.conns` / `.lines` 都是 `List<>`、**没有容量上限**
（不会溢出或截断，只是内存和连线渲染变多），而且开销落在**建造路径**上、不在 tick 路径上。
**真正要警惕的仍然是电力感应塔**那种成百上千座的，所以它的连接距离仍然只给到覆盖的两倍。

CLAUDE.md 里那句「`powerConnectDistance` 故意不动」已订正——
**一个笼统的禁令，在它拦下一个正确性问题的时候就该被重新量一遍。**

### 矿脉跟着行星面积一起放大——补一处实测的失衡

**先说结论：放大行星之后，矿脉密度悄悄掉到了四分之一，而这不是设计。**

`PlanetAlgorithm.GenerateVeins` 读了 **六次** `PlanetData.radius`，
而**一次都没进矿脉数量**：IL 0089 那处是 `2.1 / radius`——缩小每处矿脉的**角尺寸**，
好让它的物理大小不随半径变；其余五处全是高度／水面剔除的比较。
数量只来自 `ThemeProto.VeinSpot[i]`，是每个主题写死的整数。
所以半径翻倍 = 同样多的矿脉摊到 4 倍面积上。**星球变空不是错觉。**

`planet.json` 新增 `veinScaling` 段（默认开），三个旋钮，**三条推导，没有一个是挑的数**：

| 旋钮 | 推导 | 面积 ×4 时 |
|---|---|---|
| 数量 | 原版那些数是照半径 200 写的 | `VeinSpot × 4`（向上取整） |
| **种类** | **种–面积关系** `S = cA^z`，海岛生物地理学的经验律（z 实测 0.25~0.35），地质省份同理 | `4^0.25 = 1.41`，**种类 +41%**；6 种矿的主题多出 2 种 |
| 稀有概率 | **泊松** `P(≥1处) = 1 − e^(−λA)` → `p = 1 − (1−p₀)^k` | 钴 0.25 → **0.68**，钨 0.09 → 0.31，钒 0.06 → 0.22 |

泊松那条有两个自带的好性质，省掉了**全部**特判：结果**恒小于 1**（不用夹），
而且 **p₀ = 0 时仍是 0**——那正是 `RareSettings[i*4+0]`「母星系不刷」那一格。
本仓库曾经因为把那两格搞反，让四种稀有矿只长在母星系；所以这里绝不能对它特判。

**新补进来的矿种只从「在别的主题上出现过」里取**，绝不凭空造出一个谁都没打算放的矿种；
按**在别处有多普遍**降序挑（到处都有的矿最可能在这里也伴生，只在熔岩上有的不该跑到冰原去）。
密度取该主题铁矿的 0.35 倍，和 `ExtendThemes` 同一个锚——**伴生矿不是主矿，星球仍该有专长**。

> **零 transpiler、零 prefab 改动**：只在 `PostAddDataAction` 上改写 `ThemeProto` 的五个数组，
> 和本仓库注册自定义矿脉走的是同一条已验证多版的路。**必须排在 `OreRegistry.OnPostAddData`
> 之后**，否则本 mod 自己那十四种矿还没进表，效果少一半而且不报错。
>
> **只对还没生成的星球生效**；装了银河尺度则整段不生效（它换掉了整个矿脉生成），启动时明说。
> 每张主题表改写前后的矿种数和处数都会打进日志。

#### 新增 `tools/sim_veinscale.py`

三条公式离线跑一遍，并且**把本 mod 自己那五种稀有矿的改写前后真值算出来**
（`chance` 读自 `ores.json`，所以这部分是真数不是示例）。

它当场纠正了我一处不诚实的表述：断言「概率恒 < 1」在 float64 下看着成立，
但 **C# 那边 `RareSettings` 是 `Single`**，float32 精度只有约 1.2e-7，
`p₀ = 0.99` 会被舍入成正好 `1.0f`。现在按目标类型量，并明写边界在 `p₀ ≥ 0.9`
——当前最高的稀有概率是 0.35，离那里很远。**按目标类型量，别按算得方便的类型量。**

### 三氧化硫矿脉：一条直通硫酸的普通矿

```
三氧化硫 ×2 + 水 ×2 ──(原版化工厂，0.5 秒)──> 硫酸 ×2        = 4 硫酸/秒/机
```

矿种 28，**普通矿脉位**，只在**火山灰 / 灰烬冻土 / 黑石盐滩**。密度 0.8 倍铁矿。

#### 分布规则就是它的化学，两条都不是挑的

`SO₃ + H₂O → H₂SO₄` 是接触法真正的最后一步（吸收塔）——这条矿把前面的焙烧和
催化氧化当成地质过程已经做完了。而**现实的地球上不可能有 SO₃ 矿**：它熔点只有
16.9 ℃，而且遇到任何水汽就瞬间水合。两条合起来说明它只能存在于**又冷又干**的地方，
来源则是火山（SO₂ 在高空被氧化成 SO₃）。所以主题是火山灰（来源）、
灰烬冻土（既是火山的又是冷的，最合适的一类）、黑石盐滩（干，本来就是蒸发盐矿），
而**熔岩被故意排除**——那里太热，SO₃ 在那儿只会是气体。

**「快」同样不是旋钮。** SO₃ 的水合极快且强放热（ΔH ≈ −130 kJ/mol），
工业上的难题从来不是让它反应，而是**别让它反应得太猛**：真实吸收塔要先把 SO₃
溶进浓硫酸做成发烟硫酸再稀释，就是因为直接兑水会炸成一团酸雾。0.5 秒是照着化学写的。

#### 它比另外三条硫酸路都便宜，而那三条不会因此死掉

这是本仓库自己的支配性规则要回答的问题，答案是它们各自还有别的职责：
**接触法**吃渣油加氢脱硫出来的硫磺，**石膏法**吃钨线副产的石膏，**原版那条**吃精炼油。
**它们是废料的出口，不是硫酸的来源**；这一条才是「专门为硫酸开一座矿」。
要是觉得它太强，调产量和 `veinRarity`，**别动配比**——那是配平方程。

> **模型号只剩 683。** 685~727 早就排满，684 这一版刚被巨型聚变发电站占掉。
> 683 是否真空**离线读不到**，启动日志的「模型号余量」会报真值——**不是 683 就照日志改**。
> 图标是自己画的（明黄、高反光的针状结晶丛）；**纯 SO₃ 其实是白的**，
> 取的是火山硫矿场的样子（总有共沉积的单质硫），也正好和石膏矿那种暖奶油色分得开。

### 聚变线：第十七座巨型建筑，200 GW

反物质那条线卖的是「把电存起来跨星系送」，这一条卖的是**电本身**。

```
10 重氢 ──(粒子对撞机，跑这条时功耗 ×100)──> 5 氚 + 5 氢
重氢 ×20 + 氚 ×20 + 钨块 ×2 ──> 氘氚燃料棒 ×1 ──> 巨型聚变发电站 200 GW
```

新增 **2 个物品**（氚、氘氚燃料棒）、**2 条配方**、**1 座巨型建筑**，
三张图标和建筑的 3D 模型都是这个仓库自己生成的，没有引入任何第三方美术。

#### 能推的全推了，推不出来的都说是旋钮

- **`D + D → T + p` 是 D-D 的两支之一**（另一支是 `D + D → ³He + n`，各约 50%），
  所以「10 氘 → 5 氚 + 5 氕」在化学计量上是精确的。
- **氕不另开物品——它就是原版的氢。** 氕 = ¹H，一个质子零个中子，那正是原版「氢」。
  再造一个一模一样的东西出来，按本仓库自己的支配性规则就是死内容，
  而且那个新物品会**没有任何下游**。产物直接写原版氢，副产物当场有用。
- **D-T 等摩尔，所以氘 : 氚 = 20 : 20。** 钨是包壳：现实里聚变装置面向等离子体的
  那一层就是钨（ITER 偏滤器），熔点最高、最抗溅射。
- **η = 0.40 是推的**：D-T 约八成能量在 14.1 MeV 的中子上，中子不带电、穿过磁场
  打进包层变成热，再走最普通的蒸汽循环。它比氧化还原燃烧厂的 0.636 低，
  因为那一座烧的是化学火焰、可以直接上高温燃气轮机。
- **200 GW、燃料棒 1800 MJ、硬质合金 ×2000 是旋钮**，`ores.json` / `megabuildings.json` 里都注明了。
  1800 MJ 锚在实测的原版氘核燃料棒 600 MJ 上（现实里 D-T 对 D-D 的放能比是 4.8，
  这里只取 3 倍，刻意保守）。

#### 100 倍功耗不是装饰，是整条线的能量闸

观微对撞机平时 45 MW，跑氘氘聚变时 **4.5 GW**。氚只能从这一条来，
所以聚变的净产出要先把这笔电还掉。

实现上**用原版自己的公式重算一遍千分比**，而不是去改 `requiredEnergy` 的结果。
三件量过的事缺一条就会错：① `SetRequiredEnergy` 有**三个重载**，所以显式取
`(bool, int)` 那个——按名字解析会 `AmbiguousMatchException`，而那会把整个 mod 带下去；
② 三个重载**全是赋值**不是累加，再调一次是覆盖；③ `requiredEnergy` 是 **Int64**，
不会翻负。而「只有真的在跑时才 ×100」不需要额外判断——原版那个重载在
`working == false` 时直接取待机功耗、千分比根本不参与，是它自带的分支。

这个会话开头刚验证过那条教训：**这次游戏更新里带检查器的功能一个都没断，没检查器的两个全断了**。
所以聚变线出厂就带一个。它锁住四件量过的事，每一件出错都不会报异常：

```
SetPCState 的千分比仍然是 (1000 + extraPowerRatio)   ← 变了的话我们的 ×100 会算错且不报错
SetRequiredEnergy 仍然重载 3 个、(bool,int) 仍在、三个都是赋值不是累加
requiredEnergy / workEnergyPerTick 仍是 Int64        ← 100 倍不会翻负
SetNewFuel 仍公开且自己填 fuelHeat、fuelCount 仍是 Int16、烧的闸仍是 fuelCount
```

它第一次跑报了 **2 条 FAIL，两条都是它自己的毛病**——一条正则跨指令贪婪匹配，
一条断言写过头。**先确认失败是真的，再读结论**，本仓库这一条这次又验证了一遍；
而它真的会 FAIL 这件事，正是它非空的证据。

> **断言「某字段不出现」是错的写法**——字段为了别的理由被读一下，断言就炸。

### 顺手修掉两处检查器自己的毛病

这两条都不是游戏的问题，是**本仓库的检查器坏了而没人知道**。

**一、`verify_quality.ps1` 从 1.9.0 起就半死不活。** 1.9.0 把
`QualityFieldAdder.ExpectedFields` 从常量字段改成了**表达式体属性**，而脚本用的是
`GetField(...)` → 返回 null → 下一句 `GetRawConstantValue()` 当场抛出。
于是**第 174 行之后的每一条断言从那天起再没跑过**，而输出看起来像是变换失败。
这正是本文件早就记过的那条「用反射之前先确认是字段还是属性」——这次是我们的检查器
对着我们自己的 preloader 踩的。现在两种形状都认。

**二、修好之后它立刻抓到一份过期名单。** 「本 mod 调用侧信道消费方法必须全部登记」
这条断言里写的是 `HubCourierPatches::Drain` / `TopUp`，而这两个方法在 **1.10.1 被改名**
成了 `DrainAll` / `Move`——名单从那时起就过期了，**而断言正好在 1.9.0 死掉，所以没人发现**。
逐行读过两处源码确认：**gate 是对的**（取货方向「调用前清、读完再清」，入库方向
「调用前写、之后按差额结算」），没有活的品质泄漏，只是名单没跟上改名。
名单按方法名索引，所以**改名会静默让它过期**——注释里写清楚了，又是
「按名字挑，就会按名字漏」那一族。
