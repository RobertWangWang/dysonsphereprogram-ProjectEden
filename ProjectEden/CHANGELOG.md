# 更新日志

## 1.12.8

**大型采矿机的产量上限，现在和轨道采集器一样了：600,000,000/秒。**

起因是「气态行星采集器有多快，采矿机能不能跟它一致」。查下来两个数差了 **3600 倍**，
而差距的成因不在开采速度上——**开采速度早就顶满了，一点余量都没有**。

原版的产出是一句整除：`件数 = time / period`。每 tick 往 `time` 上累加
`速度 × 采矿倍率 × 矿脉数`，而 `time` 是 32 位整数，所以累加量必须留在 20 亿以内：

```
每 tick 产量 = 累加量 ÷ period ≤ 20 亿 ÷ period
```

分子这个 mod 早就顶满了（「按满级科技工作」做的就是这件事）。日志里的实测数字把话说死了：

```
抽水站产量：period=720000，当前约 166,667/秒；该建筑的理论上限约 178,957/秒——受 time 为 Int32 约束
行星 Delta Delphini II号星 气体采集速率：600000000/秒 / 69495750/秒 / 600000000/秒
```

**只剩 7% 余量**，所以再怎么调速度都动不了。剩下唯一能动的是分母。

现在 `period` **从采集器那个数倒推**。采集器的速率被夹在「一 tick 填满一个储物格」
（`stations.json` 的 `collectorMaxPerTick`，没配就退回 `slotCapacity`），也就是 1000 万/tick；
`period = 20 亿 ÷ 1000 万 = 200`，采矿机于是也落在 1000 万/tick。
**两边不是各填一个凑出来的数，而是共用同一个锚、按构造相等。**
抽水站和原油萃取站跟着各自的 `boostWaterPumps` / `boostOilExtractors` 一起走。

> **这个数在两边都是「产量不再是瓶颈」的意思，不是真的每秒搬六亿件。** 一 tick 就把机内缓存
> 和物流站槽位填满，之后卡在网络取货的速度上——采集器今天就是这样。想退回原版刻度，
> 把 `advancedminer.json` 的 `minerPeriod` 改成 `0`。

### 动之前核对过的三件事

- **`period` 全程只有三处写**——`Import`、`SetEmpty`、`NewMinerComponent`（后者取自
  `PrefabDesc.minerPeriod`）。**没有任何 UI 能写它**，所以运行时可以双向对齐，
  而不是「配置值只是默认值」那一类。
- **它进存档**，而且 `Import` 不从 proto 重新推导，所以已建成的采矿机必须在运行时补齐。
- **另外 13 处读它的全是显示与统计**（参考速率、理论产能、星球/恒星面板、采矿机面板、
  两个采集器面板），`period` 在它们的算式里同样位于分母，所以面板会跟着一起变大——
  那是**对齐**，不是被改坏。

### 一处连带修复

原版往传送带吐货的堆叠层数是 `(36000000 / period × 采矿倍率) / 1800 + 1`，`period` 也在分母上。
周期调小之后这个值会算到两万多，而 `Cargo.stack` 加宽后的上限是 **8191**。
所以它从「只抬高」改成了「抬高**并封顶**」——不封的话 Int16 回绕成负数，
就是本仓库记过的「自动集装机吃货、面板显示负数」那一类，而且一个字都不报。

**顺带**：产量上限那行日志原本整局只打一次，于是三种设备（采矿机 / 抽水站 / 原油萃取站）
里只有最先 tick 的那一种留下记录——而「另外两种是多少」恰恰是这次最需要看的数。
改成按建筑种类各报一次。

> ⚠️ **行星放大仍然默认开着**（1.12.1 起），所以**在 1.12.0 或更早版本下存的档，
> 用这一版打开就废了**。要继续用老存档，在 profile 里新建
> `BepInEx\config\ProjectEden\planet.json` 写 `{ "enabled": false }`，重开游戏即可。
