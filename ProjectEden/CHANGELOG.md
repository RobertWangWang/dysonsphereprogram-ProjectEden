## 1.12.14

### 钛合金多一条不吃硫酸的配方：Ti-6Al-4V 真空重熔

```
钛块×45 + 铝块×3 + 钒块×2 → 钛合金×50    冶炼厂，1 秒
```

配比就是 **Ti-6Al-4V**，质量分数 90 : 6 : 4 —— 全世界钛合金产量的一半是这一种牌号。
铝是 α 稳定元素、钒是 β 稳定元素，两相各占一半，这正是它既强又还能锻的原因。
按本仓库的规矩，固溶体不是化合物，所以配比写的是**质量分数**而不是配平方程。

**为什么可以不要硫酸。** 原版那条靠酸洗掉钛表面的氧化皮再合金化；这一条走的是
**真空自耗电弧重熔**（VAR），料在真空里被电弧一点点熔掉又凝回去，氧化皮根本没有
机会生成。现实里替代酸的是设备和电，**不是另一种消耗品**——所以这条配方在投料上
就是比原版便宜，没有哪种原料能诚实地补回来。

**这是一次明确的净增强，写在这里而不是藏起来。** 原版一个钛合金约
`1 钛块 + 1 钢材 + 2 硫酸`，这一条是 `0.9 钛块 + 0.06 铝块 + 0.04 钒块`，钢材和酸全省，
而且和其余 `ores.json` 配方一样**开局即解锁、不需要研究钛合金科技**（所有者的决定）。
真正的门槛是**钒**：稀有槽矿，没有钒线就跑不了这一条。

> **别指望用「配方时间长」把它扳回来。** 巨型建筑 `speedOverride = 1e8`，任何配方
> 一帧就填满 `timeSpend`，产量只受产出闸限制——`matrixTimeSpend` 那条早就记过
> 「改了时间产量一点没变」。1 秒这个数只对 1 倍速的电弧熔炉和面板显示有意义；
> 在冶铸熔炉里，熔炼类的产出闸是加法式的 `produced + 50 ≤ 100`，所以每帧 2 个循环、
> 每循环 50 个，节奏和已有的 `钒钛合金 · 熔炼` 完全一样。

**另外三件没写进配方的事，都是既有机制自己接住的：**

- **图标**故意不写 `icon` / `iconFrom`——`SyncStandaloneRecipeIcons` 会让它跟随第一个
  产物，也就是原版钛合金自己那张图。和「碳纳米管 · 聚丙烯腈碳化」同一个路子。
- **能量审计**不会报警：投料里只有铝块是可燃物（3 × 5.75 = 17.25 MJ），钛合金不是燃料，
  差额是负的。
- **原料引用一律写 `vanilla:<中文名>`** 而不是写死 ID。钛合金是 1107、钛块是 1106，
  但写错一个数字不会报错，只会静默指到别的物品上。

### 综合物流枢纽的星际运输船：64 艘 → 256 艘，而且不用 preloader

原版那 64 是**类型上限**：`idleShipIndices` / `workShipIndices` 是两个 `UInt64` 位图，
三处取位一律 `1L << (index & 63)`，所以第 65 艘的位折回第 0 位、和第 1 艘共用一格——
一艘回港会把另一艘的位一起清掉，船凭空消失或凭空多出来，**而且一个字都不报**。

**改字段类型要 preloader，改八个小方法不用——而判据是先数一遍谁碰它。**
碰这两个字段的一共 **13 个方法，全在 `StationComponent` 里**，其中八个是纯翻位的：
`IdleShipGetToWork` 整个方法就是「清 idle 那一位、置 work 那一位」，24 条指令；
最大的 `HasShipIndex` 才 25 条。`StationShipBank` 把这八个整体前缀替换成一张旁挂位图，
再转译 `ShipRenderersOnTick` 里**两处内联**取位（@0013、@0076）——那两处不走助手方法，
**只换八个够不着**，漏掉的表现是「第 65 个泊位之后的 idle 位永远补不满」，不报错。

**不占存档，这是本设计最关键的一点。** 位图整个是派生量：

- **work 位** ⇔ 在飞船的 `shipIndex`。`workShipDatas` 前 `workShipCount` 项是紧凑表
  （回港时 `InternalTickRemote` @0529 用 `Array.Copy` 往前挪），每艘带着自己的泊位号，
  而 `ShipData.Import` @0209 把它读回来了。
- **idle 位**由**原版自己**每 tick 对账补齐：`ShipRenderersOnTick` @0000–@00A1 先数出
  当前 idle 位数、和 `idleShipCount` 求差、多退少补，末尾还有一句 `Assert.Zero(delta)`。

所以读档一个 tick 之内就自己长回正确状态：**不用加存档块、不用升 SaveVersion、
老档和没装本 mod 的档都照常开**。这是「重跑派生，而不是存一份平行拷贝」（`InitFluids` 那一族）。

**已建好的站会自动补齐泊位。** `StationComponent.Init` 按 prefab 开六个数组，而 `Import`
@021B 的长度直接来自存档；原版只给运输机补了 `PatchDroneArray`（`PlanetTransport.Import`
@00C3/@00D4），**全程序集就那一个 `Patch*Array`**，运输船没有对应的。不补的话这次改动
对老站一点效果都没有——`StationShipExpandPatches` 就是缺的那一半，六个数组一起长
（漏一个会让 `ShipRenderersOnTick` 在渲染路径上越界），停泊环逐字抄 `Import` @0475–@0541。
**只涨不缩**：缩短会把停在高位泊位上的在飞船连同 `shipIndex` 一起截掉，那是丢船不是改设置。

**两条代价写在前面。** 每个泊位一条 `ShipData`（约 130 字节）加四个并行数组项，
256 泊位一座站约 25 KB；停泊环半径是原版写死的 **11.5**，泊位越多船贴得越紧，
**256 艘会明显重叠**——外观代价，不是故障。上限现在夹在 4096，夹的是内存不是位宽。

`tools/check_ship_bank.ps1` 把上面每一条前提都离线断言了一遍，**包括把转译器自己的
匹配规则也模拟一遍**（实测就是 2 处），所以游戏更新挪了形状会在那里响，而不是悄悄改一半。

### 派船额度跟着泊位一起抬到 256，顺手拆掉一条会静默生效的夹子

`remoteShipsPerDispatch` / `remoteSameRouteMax` 由 **30 → 256**。

**光改 JSON 是不够的**：`RemoteDispatchBurstPatches` 里还留着 `HardCap = 64`，
而那个 64 正是从「`idleShipIndices` 是 `UInt64`，所以一个站点至多只可能有 64 艘闲置船」
推出来的——上面那条改动把这个前提拆了，夹子却还在。留着它的后果是本仓库最讨厌的那一种：
**配置里写 256，日志读起来像生效，实际被静默夹回 64**。现在它和泊位那道夹子同源同理由，
夹的是内存不是位宽。

**按实测这个数今天多半碰不到，抬它是头寸不是提速。** 1.12.10 抬到 30 之后
「被额度打断」的比例就已经是 **0%**；抬到 256 的理由是泊位从 64 变成了 256、机队能大四倍。
碰不到的时候它不花任何代价——真正会先停下来的是环体内**原版自己的两道闸**
（`idleShipCount > 0` 和能量地板），一条都没被重写，所以额度配大了不会超发，只会够不到。

**两个数必须一起看。** 保底分散度是 `ceil(总额度 ÷ 单线上限)`，30/30 和 256/256 **都等于 1 条线**，
所以这次抬高没有再多损失一点公平性——它本来就在最差那一档（1.12.10 的决定，依据是
「一次评估平均放 8.7 艘、其中 95% 是同线连发」）。跨评估的轮转仍由游标保证。

**代价一条：能量会变得一阵一阵的。** 每次跃迁固定 100 MJ，256 艘一次评估就是 25.6 GJ，
而一座站储能 1000 GJ、充能 20 GW。真跑满会是「一口气放一批、然后卡在能量地板上等充电」，
而不是匀速。另外 `GalacticTransport.GameTick` **是主线程串行的**（没有 `_Parallel` 变体），
一次放的船越多单帧尖峰越高。想要匀一点就把这个数调小。

### 新增：运输船诊断，回答「船位到底是不是瓶颈」

问「能不能把综合物流枢纽的运输船上限调高」之前，先得知道现在有没有用满——而游戏里看不出来，
站面板只显示当前数量，不告诉你峰值。现在日志里常驻一行（不用开开关）：

```
运输船：综合物流枢纽 12 台｜在飞 31／待命 437｜单站在飞峰值 9（本局机队峰值 50）
       ｜实际船位 50，但 prefab 现在写的是 64（**这些站是抬高之前建的**……）｜位图硬上限 64
       → 远没用满，瓶颈不在船位（先看派船节奏和充能）
```

每 10 秒看一眼脚下这颗星球，**数字有变化才报**，所以不会刷屏；峰值是会话级的，
所以「这一局有没有顶到上限」抓一次日志就答得上。

**顺带把两件一直看不见的事摆出来了：**

- **64 是类型级硬上限，不是配置定的。** `idleShipIndices` / `workShipIndices` 都是 `UInt64`，
  而三处取位一律 `1L << (i & 63)`（`AddIdleShip` @000A、`QueryIdleShip` @0018、`HasShipIndex` @0009
  和 @0019）。第 65 艘船的位折回第 0 位、和 0 号船共用一格，一艘回港会把另一艘的位一起清掉——
  **而且一个字都不报**。
- **1.12.10 之前建的枢纽还是 50 艘，不会自己长。** `StationComponent.Init` 从
  `PrefabDesc.stationMaxShipCount` 开六个数组，而 `Import` @021B 先 `ReadInt32()` 再按那个数
  `newarr`——长度来自存档，**不重算**。对照无人机那一侧，原版自己是有补正的
  （`PlanetTransport.Import` @00C3 现读 prefab、@00D4 调 `PatchDroneArray`），
  **但全程序集只有这一个 `Patch*Array`，运输船没有对应的**。想要 64 艘只能拆了重建。

诊断本身有开机状态行，读的是 Harmony 自己的补丁表——**状态行回答「接上了没有」，
事件行回答「它决定了什么」**，所以「一行运输船都没有」只可能是这颗星球上没有星际站。

### 顺手修掉两份特性指南里一条错了很久的配比

`钒钛合金 · 熔炼` 在两份指南里都写成「钒块×4 + 钛块×6」，而配置里是
`钛块×42 + 钒块×8`——**钒钛两味的比例反了**（表里其余各行是按 1/5 缩写的，这一行不是）。
现已改成「钛块×8 + 钒块×2」。
