# 扫描函数的手工重建与整段差分核验

基于 `10632090` 的完整机器码和已穷举验证的 `106392d0` 分类器，新增 `tools/dsp_scanner_reference.c`。它消除了原 Ghidra C 中错误的 `extraout_ECX`、EDX 拼接返回等推断，使用明确的指针推进和分类逻辑。

这是**手工重建参考**，不是原始源码或未修改的 Ghidra 输出。参考函数接收 256 字节 `classification` 表指针，对应原对象的 `+0x4c`；原始 Ghidra 文件、函数体修复结果和内联实验均保留。它也不是建议直接替换游戏实现的补丁。

## 对照方法

验证脚本每次使用 MSVC 重新编译当前参考 C 为本地测试 DLL，记录构建参数及哈希，再逐项与 Unicorn 中的**原始扫描器和原始分类器机器码**比较。没有把分类器替换为返回固定值的桩。

第一批共 **6,816 组人工分类表测试**：所有 256 种人工初始分类值配合短长度边界、256 种首字节配合四类次字节、分类组合与结束符序列、以及固定种子的 3,000 组随机输入/分类表。包含未对齐起点、奇偶长度、空输入与保留输出指针的提前返回。后续加入 139,374 组二进制内静态分类表测试，当前合计 **146,190 组**，两个测试组分别统计。

每组检查：

- EAX 返回值与手工 C 返回值一致。
- 输出指针的相对偏移一致，未写输出时仍保持哨兵。
- ESP 返回后仅弹出返回地址；EBX、EBP、ESI、EDI 保持。
- 原始机器码没有写入输入缓冲区或分类表，其他写入仅限调用栈及输出槽。

人工分类表组覆盖全部 **160 条扫描指令**。该组返回分布为：`-4` 442 次、`-1` 457 次、`-2` 32 次、`0` 761 次、`6` 4,984 次、`7` 139 次、`40` 1 次。静态表组覆盖 140 条指令，未将人工表能触发的所有路径当成实际静态配置下可达。

## 二进制内静态对象与分类表

PE 重定位及原始指针共同确认两个槽引用 `10632090`：`10bc9e88`、`10bc9ff8`。其附近有两组一致的 17 个函数指针，候选对象基址又被其他静态指针引用：

| 对象基址 | 扫描函数槽（+8） | 分类表（+0x4c） | 引用基址的静态槽 |
| --- | --- | --- | --- |
| `10bc9e80` | `10bc9e88` | `10bc9ecc` | `10bc92e0`、`10bc92e4` |
| `10bc9ff0` | `10bc9ff8` | `10bca03c` | `10bc92c4`、`10bc92c8` |

验证脚本逐次检查这些指针值，从游戏文件直接读取两张 256 字节表。两表只有 `0x3a`（冒号）不同：前者分类 23、后者 22。它们在本扫描函数的两处分派都走大于 10 的默认路径；不能由这个差异自行推定整个解析器的模式或配置名称。

其他关键字节的分类相同：NUL→0、LF→10、CR→9、`]`→4、`>`→11、`A`→24。表内没有人工测试可生成的某些分类值，尤其分类 5、6。

每张原表测试全部 65,536 个单个双字节输入、4,096 组固定种子的多字符与长度测试，以及空串、CR/LF、冒号、`]]>` 等的每个前缀长度，共每表 **69,687 组**、合计 **139,374 组**。该组对照全部通过，观察到 **0 次逻辑 end 后读取**；返回统计在报告的 `profiles.static_tables` 单列。

这证明所检查二进制中的静态表及其对应扫描结果。尚未找到完整运行时选择路径，也未证明对象不会被复制/修改；因此不把静态表测试称为全部真实运行环境的安全或语义证明。

## 必须保留的限制

输入使用分配好的 512 字节缓冲区及零填充尾部。人工分类表组保持 `table[0]=0`，其中 **62 组**原始代码读取了逻辑 `end` 之后、但仍在已分配缓冲区内的字节；静态原表组未观察到这一现象。报告保存前十个人工表案例的原始输入、完整分类表、长度、对齐和读取偏移，供后续研究真实调用约束。

不能把这些人工组合直接当成真实游戏会触发的问题，也不能把有限对照通过解释成“不越界”或真实输入安全证明。静态表已找到，仍需追踪调用方、运行时选择及输入前置条件。参考 C 的适用测试域为向前、地址差不发生 32 位回绕的已分配缓冲区；未证明所有输入、所有调用环境等价。

## 复现与查询

需要 `cl.exe`、Capstone、Unicorn：

```powershell
python -X utf8 tools/dsp_native_scanner_reference.py
python -X utf8 tools/dsp_native_query.py 10632090 --module rail_api.dll --scanner-reference --show
```

默认查询仍显示 Ghidra 函数体修复结果，并提示手工参考位置；只有显式 `--scanner-reference` 才显示手工重建稿。构建产物、重建稿副本、完整报告和清单位于所选模块的 `scanner-reference/`，均属本机生成内容。
