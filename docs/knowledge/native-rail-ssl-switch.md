# rail_api.dll 的 SSL 初始化跳转表恢复

固定 32 位 `rail_api.dll` SHA-256：`c0094678b3cf3a026413f3fcddab3982e3381f1f34ece3473bdb865f8184cad1`。

上一批 `1052489e`、`105248a6`、`105248ae` 三个候选的 C 导出报参数变量调整错误。只读引用检查确认，它们来自原函数 **`105245a0`** 内 `10524897` 的绝对跳转表 `10524ecc`，是原分析遗漏的内部路径。不能再把这三项理解为三个尚未恢复的独立源码函数。

原 C 在这里报无法恢复跳转表并将间接跳转当成调用，提前结束函数。恢复父函数范围 `105245a0..10524ea9` 后，完整导出 **2,314 字节、646 条指令**，逐指令与游戏文件核对，覆盖连续范围且无重复或缺失字节。

## 两级分派

首处分派 `10524784` 对 EBP 作无符号 `>7` 检查，再在 `1052478d` 读取 `10524eac` 的八项表。第二处 `10524897` 读取栈内保存的索引并使用 `10524ecc`。表的真实映射如下：

| 索引 | 第一处分派目标 | 第二张表目标 | 第二处分支片段 |
| --- | --- | --- | --- |
| 0、1 | `10524794` | `105248a6` | ECX 按位 OR `0x02000000`，跳到 `105248cc` |
| 2 | `10524e5a` | `10524e5a` | SSLv2 不支持错误路径 |
| 3 | `10524e6c` | `1052489e` | ECX 按位 OR `0x1c000000`，跳到 `105248cc` |
| 4、5、6、7 | `10524794` | `105248ae` | 转入 `10525f90` 辅助函数调用路径 |
| 无符号大于 7 | `10524e7e` | 不在第二张表范围内 | 参数错误路径 |

第一处分派会将 2、3 引向错误路径；第二张表仍保留对应槽位。模拟第二张表全八项只是核验机器映射，不意味着从父函数正常入口都能到达。两个分派之间有外部调用，本轮没有证明任意被调函数不会修改相关内存。

在第二处分派前，AL 为零时选取 `0x80024054`，非零时保留 `0x80024854`，先把该值写回栈中的选项槽，然后执行上述分派。这些常数是原始位模式；未借常数猜测所有 OpenSSL 版本中的宏定义。

## 反编译器重复标签缺陷与核验边界

仅增加流引用仍不能恢复该分派，因此使用 Ghidra 手工跳转表覆盖，原 C 保留 `Switch is manually overridden` 提示。即使向覆盖 API 传入完整八项（含重复地址），生成 C 仍只保留通往辅助函数路径的 `case 4`，遗漏 `case 5/6/7`；这些值会错误落入 default。

保留原始 `105245a0.c`，另生成 **`105245a0.corrected.c`**，仅在该辅助调用分支前补回三个重复标签并加入说明。统一查询使用修正稿；不能把它描述为未修改的原始 Ghidra 输出。

`dsp_native_rail_ssl_switch.py` 完成：

- 全父函数原始字节、独立指令边界和覆盖核验。
- 36 组第一处分派测试，包括无符号边界和负整数对应的位模式。
- 8 个第二张表项 × 256 个 AL 值，共 2,048 组原始 x86 指令模拟，核验目标、ECX、栈选项值和 ESP。
- 总计 **2,084 组**，涉及 13 条分派片段指令；不执行任何外部辅助函数。
- 解析修正 C 的这一个 switch 映射，与机器映射核对；删除 `case 5` 的负向用例被拒绝，原始 C 的重复标签问题也会被检出。

这没有证明整个 SSL 初始化函数、TLS 会话、证书校验、网络 I/O 或被调函数行为等价。修正后 C 可用于继续追踪配置、ALPN、SNI、证书及回调设置；运行时字符串中的 `WARNING:` 不是反编译器警告。
