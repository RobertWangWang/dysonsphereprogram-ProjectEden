# 三个属性读取函数的浮点 ABI 修复

## 分发表追踪与五个新增入口

在固定 PE 数据中定位读取函数地址后，Ghidra 引用追踪找到四处分发表安装代码。独立复核实际 `LEA RAX,[table]` 与紧随的 `MOV [R9],RAX`，而非仅依赖 C 中的全局名称：

| 表基址 | 安装函数 | 第 0 槽 |
| --- | --- | --- |
| `181a50be0` | `180b4f330` | `180b4b7e0` |
| `181a50c20` | `180b54940` | `180b4be10` |
| `181a50c60` | `180b54bb0` | `180b4be10` |
| `181a512d0` | `180b4b100` | `180b52ee0` |

本轮检查每组**前 8 个槽位**，共 32 个函数指针；这不是完整表长度证明。这些表属于读取接口本身，不等于下面目标对象的虚表，因此还不能据此确定目标对象 `vtable+100` 的真实实现。

其中五个不同入口未在原索引或此前补充索引中，现已全部补建并导出 C/汇编，**197 字节、62 条指令，C 无警告**。每条机器字节与原 DLL 一致，导出范围完整覆盖，原项目回滚。结合原始指令与新 C，可记录以下行为；未对这些新增函数执行运行时模拟：

| 新入口 | 静态恢复行为 |
| --- | --- |
| `18038d360` | 对 RDX 指向的结果写入 `+24 = DWORD 0x49`、`+0 = BYTE 0`、`+18 = BYTE 0x18`、`+20 = BYTE 1`，返回该指针 |
| `180b4bf90` | 以描述符高 28 位为索引，检查对象 `+68` 数量，读取 `*(object+58) + index*8` 的前 4 字节；越界返回 0 |
| `180b53290` | kind 5 读取对象 `+b8`；kind 6 按上述数组规则读取前 4 字节；其他返回 0 |
| `180b4bde0` | 将 R8 指向对象的 `+4` DWORD 零扩展写入 R9 指向的 QWORD；低四位为 7..10 时返回 `181c42160`，11 时返回 `181c42480`，其余返回 `181c42110` |
| `180b53350` | 同样复制选择值；低四位为 1..4 时返回 `181c42160`，5..6 时返回 `181c42480`，其余返回 `181c42110` |

三个全局返回地址的正式注册类型名仍未确认。后续提取的 [原生属性目录](native-property-catalog.md) 以 347 条具名记录支持其中两个地址的浮点/布尔行为解释；第三个仍未知。数组中前 4 字节由新增读取函数访问、后 4 字节由浮点读取函数访问，可作为后续恢复元素结构的证据，不能直接推断其语义名称。

发现证据保存于 `reader-table-discovery/`；导出、字节验证与清单保存于 `reader-table-callbacks/`，均在 Unity 原生生成目录下。查询已合并五个入口，累计三批补充入口为 2,910 个。复现：

```powershell
python -X utf8 tools/dsp_native_reader_tables.py
python -X utf8 tools/dsp_native_crt_callbacks.py --reader-tables
python -X utf8 tools/dsp_native_query.py 180b53350 --module UnityPlayer.dll --show
```

两条 Python 命令之间需执行只读 Ghidra 导出：`DspCrtCallbacks.java` 的三个参数依次为 `reader-table-discovery/missing-entries.txt`、`reader-table-callbacks` 输出目录和 `reader-table-discovery/report.json`。Ghidra 再次从原程序逐项核验槽位指针后接受入口。`DspReaderTableRefs.java` 可重新生成四组表基址的原始引用报告。

`180b4b7e0`、`180b4be10`、`180b52ee0` 的原 C 将返回值推断为 `ulonglong`。真实指令在普通返回路径使用 `MOVSS/XORPS XMM0`，通过 `XMM0` 低 32 位返回单精度数。`RAX` 留有指针或临时值，不能当作返回值。三个函数均已重新导出为 `float`，并补充虚函数尾调用处的浮点签名。

原“无法恢复跳转表”警告实际位于 `JMP qword ptr [RAX+0x100]`，其中 RAX 来自对象首地址处的虚表指针。调用前已恢复栈及非易失寄存器，因此这是动态虚函数尾调用，不能添加一组任意固定跳转目标冒充恢复完成。原间接跳转警告保留。

## 可复用的布局信息

描述符由 RDX 传入：`+0` 为 32 位选择值，`+0x18` 为对象指针。选择值低 4 位决定种类，高 28 位可作数组索引。首个 RCX 参数在这些函数体中未读取，修正原型中标作 `unused`；这不确定其调用者侧的业务含义。

| 行为 | 180b4b7e0 / 180b4be10 | 180b52ee0 |
| --- | --- | --- |
| 普通浮点字段 | kind 0/1/2/4/5/6 → 对象 +7c/+80/+84/+88/+8c/+90 | 无 |
| 浮点虚函数尾调用 | kind 3，虚表 +100 | kind 0，虚表 +100 |
| 标志转换为 0.0 / 1.0 | kind 7/8/9 → 对象 +94 的 bit 0/1/2 | kind 1/2/3 → 对象 +c0 的 bit 0/1/2 |
| 布尔虚函数再转浮点 | kind 10，虚表 +110，按 AL 非零判断 | kind 4，同一偏移 |
| 数组元素 | kind 12 | kind 7 |
| 其他种类或数组越界 | 0.0 | 0.0 |

数组步长 8 字节，元素中 `+4` 位置是返回的浮点值。`180b4be10` 和 `180b52ee0` 从对象 `+58` 取数组指针、`+68` 取 64 位数量。`180b4b7e0` **无论选择何种属性，首先调用虚表 +130** 获取容器，然后从容器 `+0` 取指针、`+10` 取数量。不能删去这一调用或假定它没有副作用。

常量 `181aecba8` 原始位模式为 `3f800000`，即 1.0f。以上仅给出实际偏移和行为，具体对象类名、属性名称及虚函数实现尚未确定。

## 验证与限制

离线执行三个完整读取函数的原始机器指令，虚方法采用受控返回桩。每个函数 4,264 组、合计 **12,792 组**输入通过，覆盖全部 16 个种类、256 种标志字节、数组索引/长度边界、AL 判断和正负零/无穷/NaN 位模式。核对 XMM0 低 32 位、整个模拟对象未修改、虚调用次序及 this 指针、返回地址、RSP、RBX/RDI 和写入范围。

三个函数合计执行全部 **266 条非填充指令**，每个只剩末尾 1 条 NOP 未执行。每个函数均有 4,006 组输入的 RAX 低 32 位与浮点返回值不符，直接说明原整数返回解释不能使用。将 1.0 常量改成 2.0 的三个负向用例均被拒绝。

测试证明受控桩条件下读取函数的行为，未验证具体虚表类身份、真实虚方法行为、并发修改或无效指针。重新导出的 C 保留间接尾调用警告，不视为全程序等价证明。

证据位于 `generated/native/UnityPlayer.dll/float-readers/`：3 份修正 C、完整函数区间汇编、导出报告、模拟验证报告与哈希清单。原 Ghidra 项目所有修改回滚。

```powershell
python -X utf8 tools/dsp_native_float_readers.py
python -X utf8 tools/dsp_native_query.py 180b52ee0 --module UnityPlayer.dll --show
```

导出使用 `DspRepairFloatReaders.java`，在固定 Unity 项目以 `-readOnly -noanalysis` 执行，唯一参数为上述证据目录。查询会校验清单后优先显示浮点返回修正版。
