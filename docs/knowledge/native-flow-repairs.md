## `180cd2ed0` 不可达块的核验

候选 C 的八条警告并非遗漏真实分支。`dsp_native_dead_branch.py` 从原始 DLL 完整解码函数 `180cd2ed0..180cd33a1`，覆盖 **1,234 字节、306 条指令**，建立保守的函数内控制流：普通调用视为可以返回，唯一间接跳转使用已核验的两项 RVA 目标。

区域 `[180cd32d2,180cd3343)` 的唯一外部进入边为 `180cd32bb → 180cd32d2`。入口判断块 `180cd32b8` 又只有来自 `180cd316c` 的一条进入边：

```text
180cd3166  cmp   edx, ecx
180cd3168  setne r9b
180cd316c  jne   180cd32b8
...
180cd32b8  test  r9b, r9b
180cd32bb  je    180cd32d2
```

`setne` 不改变比较产生的标志位。能沿 `jne` 到达后一个判断时，`r9b` 必为 1，因此 `test` 后 ZF 必为 0，`je` 不可能成立。没有其他函数内直接或已解析间接边进入该区域。这个推导与两个比较值的具体数值无关，覆盖正常入口出发的这条控制流；不声明任意外部跳入函数中部或异常控制转移也满足该结论。

独立 CPU 模拟使用五个典型 32 位值两两组合，以及两种初始 `r9`，共 **50 个用例**。只可能到达相等路径 `180cd3172` 或不等路径 `180cd32bd`，没有进入被删除区域。将模拟器内 `SETNE` 改为 `SETE` 后，负例立即发现进入错误分支；没有修改磁盘游戏代码。

证明保存在 `quality-repair/180cd2ed0/dead-branch-proof.json`，包括完整函数字节哈希、解码覆盖、唯一进入边、谓词原始字节及全部模拟结果。核验器要求这八条不可达警告与记录中的地址逐条一致，同时核对旧的 624 个选择器模拟用例；不接受额外未知警告，也不删除已证明原因的原警告。

## `18177f9f0`：六张表与重复目标问题

已为这处剩余异常生成独立候选，尚未加入优先查询列表。函数正常代码范围为 `18177f9f0..18177fb3b`，随后为表数据。六处跳转对应：

第一次对所有表写入 BasicOverride 的候选暴露了重复目标问题：输入 4 和 5 的 RVA 相同，但生成 C 只保留 `case 4`，导致 `case 5` 路径缺少变量赋值。该文件保存为 `duplicate-target-candidate-18177f9f0.c`，**禁止作为正确恢复结果使用**。

修正方法改为：直接 RVA 表只重建引用，让反编译器恢复重复 case；仅对两张字节索引表使用 override。此前未解码的合法目标在函数限定范围内补反汇编。新候选已恢复 `case 4: case 5:`，消除了 `halt_baddata()`，但仍有 `18177fa8b` 的间接跳转恢复警告，因而继续保留候选状态。

入口的原始检查为无符号 `输入 - 1 <= 4`，正常路径只允许输入 1..5。基于原始指令得到的待核验行为摘要：源指针为空或输入不在 1..5 时返回 0；偏移为零时不调用复制函数；其他情况下，复制参数为 `目标基址 + uint32(偏移)`、源指针和 `uint32(系数 × stride)`，系数依输入 1..5 分别是 4、8、12、16、16，随后将偏移字段清零并返回 0。该摘要限正常入口及外部调用正常返回的情况。

`dsp_native_multistage_probe.py` 在 Unicorn 中模拟完整原函数的正常入口，但把外部 `181835930` 调用替换为“记录寄存器参数＋RET”，不会执行其实际内存复制。23 种输入、4 种 stride、3 种偏移、2 种源指针状态，共 **552 个用例通过**；同时检查返回值、偏移更新和栈恢复。把模拟器内输入 5 的 RVA 改到输入 1 的目标时，负例检测到复制长度错误。

工具还从原 DLL 独立重读六张表，核验全部 **96 个映射**，记录候选 C 和报告哈希。结果在 `quality-repair/18177f9f0/normal-entry-probe.json`，状态明确为 `candidate-not-promoted`。这些证据不证明外部复制的内存副作用，也不证明候选 C 与机器码全等；下一步仍需核对不可达通用分支及剩余警告。
