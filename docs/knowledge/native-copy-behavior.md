# Unity 复制过程与六表调用者

## 从调用桩推进到真实内存结果

六表函数 `18177f9f0` 调用的 `181835930` 已进一步分析。此前的 552 个入口用例只捕获参数并用 RET 模拟返回；本轮新增测试会在 Unicorn 中执行 **原始复制过程及其 REP 助手的实际机器码**，不使用复制实现桩，也不启动游戏进程。

原始 C 与反汇编显示长度分派、源/目标重叠判断、向前和向后复制。抽样结果符合基于源缓冲区快照的重叠安全复制语义；可将它作为后续查询的行为参考，但原始符号名尚未恢复，不能仅凭这些样例确定它在原工程中叫 memcpy 还是 memmove。

| 地址 | 范围 | 已识别作用 |
|---|---|---|
| `181835930` | `181835930..181835d04`，981 字节 | 短长度分派、SIMD 前向/后向复制和实现选择 |
| `181835910` | `181835910..181835922`，19 字节 | 保存 RSI/RDI、执行 REP MOVSB、恢复寄存器并返回 |
| `181e76f30` | 68 字节 | 长度 0..16 的 17 项 RVA 表 |
| `181cbdc60` | 使用低字节 bit 1 | 大于 128 字节时的 REP 路径选择 |
| `181c41248` | 8 字节阈值 | 前向大块复制路径的阈值比较 |

REP 助手从 R10 取得源地址、R8 取得长度、R11 取得返回目的地址。它依赖上层过程准备的寄存器状态，不适合按原 Ghidra 推断的普通三参数 void 函数独立调用。反汇编明确执行 `mov rax,r11`；测试检查整段复制返回目的地址，而非依赖旧的 C 返回类型。

## 测试范围

`dsp_native_copy_probe.py` 固定游戏 SHA-256，并把需要的原代码、跳转表和测试内存映射到模拟器。源和目标位于同一 64 KiB arena，使用包含不同地址信息的初始字节模式。预期结果由复制前源区快照生成；执行后比较 **整个 arena**，同时限制写入仅发生在目的区、栈和调用者应清零的偏移字段，防止只检查目标片段而漏掉越界破坏。

**3,528 个直接复制用例：**

- 长度 0..33，以及 63/64/65、127/128/129、255/256/257、1023/1024/1025、4095/4096/4097。
- 4 种源地址对齐；目标与源相同、前后相差 1 或 17 字节，以及分离缓冲区，共 6 种布局。
- 模拟能力字节为 0 或 2，阈值为 0 或较大值，合计 3 种组合。这些是测试输入，不声称它们等于当前游戏进程的初始化值。

**560 个调用者联调用例：**从 `18177f9f0` 真正进入复制过程，覆盖类型 0..6、5 种步长、零/非零偏移、空/非空源指针、两种能力字节和重叠/分离目标。检查完整复制结果、调用参数、返回零及偏移字段更新，弥补了先前使用 RET 桩时未验证的部分。

所有用例还检查栈指针与非易失通用寄存器恢复。记录证明 REP MOVSB、后向路径和全部已识别的 MOVNTPS 非临时存储位置均被执行。将长度 1 的 RVA 改向长度 0 的返回路径后，负例检测到复制结果错误；游戏磁盘文件保持原样。


证据位于 `generated/native/UnityPlayer.dll/copy-behavior/`：`report.json` 含 4,088 个用例、路径覆盖、输入代码/表哈希及结果哈希，`copy.asm` 为主体的完整反汇编，manifest 固定输出哈希。查询显示抽样证据提示，同时保留原 C 或已有的定点修正 C，不新增函数完成计数。

结论限有效映射的测试缓冲区、DF=0 的调用约定、选定能力/阈值输入及已列出的长度。未覆盖所有长度、访问异常、并发修改、真实缓存/内存排序效应或生成 C 的完整类型等价。模拟器验证实际字节结果，不构成在真实硬件和全部环境下的全函数证明。
