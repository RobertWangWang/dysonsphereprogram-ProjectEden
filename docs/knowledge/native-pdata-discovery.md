## 已修复候选：180961d40 的类型分派

已补回 `180961e53` 的跳转表目标，重新导出 `quality-repair/180961d40/180961d40.c`。自动恢复仍失败，因此使用显式跳转表覆盖；原来的“无法恢复跳转表”和“将间接跳转当作调用”警告消失，保留一条 `Switch is manually overridden`。原项目操作回滚，原始导出和下述覆盖审计仍作为历史基线保留，不将本次修复重复计为新增函数。

原始 `+16c` 字段的值 5、7、10 分别走特殊参数准备路径，其余值经过无符号 `(kind - 4) <= 6` 检查。进入表的所有路径索引均在 0..6：`180961eb0` 的 7 个 RVA 表项合计指向 5 个不同地址。恢复出的分支行为如下，字段尚无已证实的业务名称：

| kind | 本片段的字段写入 |
| --- | --- |
| 4、8、9 | `+17c = +1d8` |
| 5 | 将 `+184` 原值写回，然后 `+17c = +1d8` |
| 6 | 无写入 |
| 7 | 将 `+17c` 原值写回 |
| 10 | `+184 = ((uint32)(old184 * 6)) / 6`，随后 `+17c = +1d8` |
| 其他 | 不经过表，本片段无字段写入 |

类型 10 的乘法发生 32 位回绕，随后用乘法高位与右移实现无符号除以 6，不能对所有输入化简为保持原值。类型 5 写回 `+184` 后还会贯穿执行对 `+17c` 的写入。

`tools/dsp_native_texture_switch.py` 对原始 `180961dee..180961e74`（末端不含）的 134 字节、34 条指令离线执行 2,640 组输入，覆盖所有指令；检查完整 512 字节模拟对象、写入地址/宽度、间接分派目标和汇合地址，包含乘法溢出边界及高位类型值。修改第一个表项的负向用例被拒绝。未执行前后的辅助函数或游戏 API，因此不构成整个函数的等价证明，文件名中的 texture 也不作为业务类型已确认的证据。

## 实际函数体覆盖

对全部记录范围与原 Ghidra 项目函数体的并集求交：86,858 条完全覆盖，6,970 条部分覆盖，50 条完全不覆盖。未覆盖区域共 **7,896 个区间、80,863 字节**。这表示函数体集合存在空隙，不等于这些字节全部都是遗漏代码。

按 Ghidra 列表原分类，空隙中有 3,733 字节已定义指令、42,238 字节已定义数据、34,892 字节未定义内容。独立按原始字节核对，剔除 Ghidra 已定义数据后，仅当剩余连续片段完整解码为 NOP/INT3 才将区间归入填充类：

| 区间分类 | 字节数 |
| --- | ---: |
| 完全由 NOP/INT3 构成 | 10,220 |
| 已定义数据与 NOP/INT3 组合 | 35,376 |
| 仍需分析的混合或指令区域 | 35,267 |

最后一类包含 **283 个区间、138 个根函数**，全部保存原始字节、展开链根入口与未排除片段。分类不能证明填充不可达，也不能证明 Ghidra 数据类型判断正确；保留全部原始缺口，便于重新分析。

具体候选：`180961d40` 的原 C 在 `180961e53` 报告跳转表未恢复，将跳转当作调用。其范围内 `180961e55..180961e74`（末端不含）含未归入函数体的代码，另有跳转表附近数据区间。应继续结合索引约束和真实分支目标恢复，不能直接把所有空隙当作代码添加。另一些候选只是共享尾声中的寄存器恢复指令，需要区分函数边界问题与丢失业务分支。

## 工具与证据

`generated/native/UnityPlayer.dll/pdata-discovery/` 中：

- `records.json`：全部目录记录、完整展开链关系和输入索引哈希。
- `coverage.json`：Ghidra 实际函数体覆盖、缺口范围、已定义代码/数据细目及输入文件哈希。
- `gap-audit.json`：逐区间原始字节和独立分类。
- `candidates.json`：283 个待处理区间及所属根入口。
- `manifest.json`：上述文件的完整性哈希。

复现顺序：运行 `tools/dsp_native_pdata_discovery.py`；在原 Unity 项目用 `-readOnly -noanalysis` 执行 `DspAuditPdata.java`，参数依次为 `records.json` 和 `coverage.json` 的绝对路径；最后运行 `tools/dsp_native_pdata_discovery.py --verify-coverage`（此步需要 Capstone）。

此次没有增加 C 完成数量。实际成果是排除重复分段入口、建立可验证的代码覆盖缺口队列；全量函数发现、控制流与语义恢复仍未完成。
